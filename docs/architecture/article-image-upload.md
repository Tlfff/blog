# 文章图片上传流程

## 1. 设计目标

文章图片在文章创建前作为未绑定资源实时上传，正文只保存稳定的 `image://<image_id>` 占位符。对象公开域名由配置提供，详情查询时根据图片记录生成 URL。

图片对象使用以下路径：

```text
article/img/<year>/<month>/<uuid>.<ext>
```

路径不包含文章 ID；文章归属由 `article_images.article_id` 表达。

## 2. 实时上传

1. 用户在编辑器粘贴或选择一张图片。
2. 前端调用 `POST /admin/article/image/upload-url`，请求体为 `{"file_ext":"png"}`。
3. 后端校验扩展名，生成对象 Key 和预签名 PUT URL，并创建 `article_id = NULL` 的图片记录。
4. 接口返回 `image_id`、`upload_url` 和当前公开 `url`。
5. 前端 PUT 上传成功后，在原始 Markdown 中写入 `image://<image_id>`，并使用响应中的 `url` 实时预览。

预签名 URL 会过期，不写入数据库；图片表只保存对象 Key 和文章归属。

## 3. 创建和更新文章

创建文章时，后端解析正文中的系统图片 ID，在同一数据库事务中创建文章并绑定未归属图片。

更新文章时，后端比较新旧正文图片引用：

- 新增图片：从 `article_id = NULL` 绑定到当前文章。
- 保留图片：保持当前文章归属不变。
- 移除图片：将 `article_id` 设回 `NULL`，本次不立即删除对象。
- 无效图片：不存在或已属于其他文章时拒绝保存，并回滚正文和图片关系。

历史完整图片 URL 和外部图片 URL 保持不变，不参与图片关系同步。

## 4. 文章详情

公开详情和管理员编辑详情均返回数据库中的原始 `content`，并增加正文图片映射：

```json
{
  "content": "![示例](image://123)",
  "images": [
    {
      "id": 123,
      "url": "https://cdn.example/article/img/2026/08/example.png"
    }
  ]
}
```

前端编辑状态始终保留原始占位符，只在 Markdown 渲染阶段使用 `images` 映射展示图片。更新文章时不需要把公开 URL 反向转换为图片 ID。

## 5. 删除行为

- 文章软删除和恢复不改变图片归属。
- 文章硬删除前按 `article_id` 查询图片并逐个删除 OSS 对象。
- 任一对象删除失败时保留文章和图片记录，以便重试。
- 对象全部删除后，在同一数据库事务中删除图片记录和文章记录。

上传后未使用或编辑后解绑的图片保持 `article_id = NULL`。本次变更不实现孤立图片定时清理，后续可按创建时间和宽限期增加回收任务。
