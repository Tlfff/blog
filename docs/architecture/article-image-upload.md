# 文章图片上传流程

## 1. 设计目标

文章图片直接上传到 `article/<article_id>/` 正式目录，不再要求新流程先上传到临时目录后执行 OSS Copy 和 Delete。创建和更新都由前端等待本次新增图片全部上传成功后，再提交包含正式 URL 的文章正文。

## 2. 创建文章

前端点击创建按钮后按以下顺序执行：

1. 调用 `POST /admin/article/init` 初始化空内容草稿，取得 `article_id`。
2. 收集正文中的本地图片，通过 `POST /admin/article/image/upload-urls` 批量获取上传凭证。
3. 并发 PUT 图片到 OSS，并等待全部上传任务成功。
4. 使用响应中的正式 URL 替换正文占位符。
5. 调用现有 `POST /admin/article/update` 保存标题、正文、标签和目标状态。

初始化草稿固定使用草稿状态，不新增数据库字段或文章状态。用户中途放弃创建时，空草稿继续保留，可再次编辑或移入垃圾箱。

## 3. 更新文章

更新时已经拥有 `article_id`，前端只处理本次新增的本地图片：

1. 批量获取新增图片上传凭证。
2. 并发上传到当前文章正式目录，并等待全部任务成功。
3. 替换本地图片占位符，调用现有更新接口保存最终正文。

正文已有远程图片无需重新上传。正文移除图片引用时不删除 OSS 对象，避免误删并保持实现简单。

## 4. 批量上传凭证接口

请求示例：

```json
{
  "article_id": 123,
  "files": [
    {
      "client_id": "image-1",
      "file_ext": "png"
    },
    {
      "client_id": "image-2",
      "file_ext": "jpg"
    }
  ]
}
```

响应数据示例：

```json
{
  "files": [
    {
      "client_id": "image-1",
      "upload_url": "<presigned-put-url>",
      "url": "https://cdn.example/article/123/<uuid>.png"
    },
    {
      "client_id": "image-2",
      "upload_url": "<presigned-put-url>",
      "url": "https://cdn.example/article/123/<uuid>.jpg"
    }
  ]
}
```

每个文件独立携带扩展名，后端在签发任何凭证前完成整批校验。非文章作者、已软删除文章、空文件列表或任一非法扩展名都会导致整个请求失败。

## 5. 上传时序约束

浏览器可以异步并发上传，但必须等待全部 PUT 请求成功后再更新文章。提前保存正式 URL 会产生正文已落库但图片不存在的风险。

刷新或关闭页面通常会中断尚未完成的浏览器上传任务。前端应展示上传进度，并在上传期间提示用户离开页面的风险；本项目不提供页面关闭后的后台续传能力。

## 6. 删除策略

- 草稿、已发表和软删除文章均保留其目录下的全部图片。
- 更新正文移除图片引用时不删除 OSS 对象。
- 只有硬删除垃圾箱文章时，才删除 `article/<article_id>/` 前缀下的全部对象。
- 硬删除先清理 OSS，再物理删除数据库记录；OSS 清理失败时保留文章记录，以便重试。
- 如果 OSS 已清理但数据库删除失败，文章仍在垃圾箱，重试时空目录按清理成功处理。

## 7. 接口约束

文章图片只使用 `POST /admin/article/image/upload-urls` 批量正式目录接口。旧单张临时凭证接口、临时对象路径和图片转正逻辑已经移除，创建和更新接口接收的正文必须已经包含正式图片 URL。
