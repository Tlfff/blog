## ADDED Requirements

### Requirement: 单图片实时获取上传凭证
系统 SHALL 允许唯一管理员在不提供文章 ID 的情况下为单张合法图片申请上传凭证，并 SHALL 返回图片 ID、预签名上传 URL 和当前公开访问 URL。

#### Scenario: 获取单张图片上传凭证
- **WHEN** 管理员提交一个合法图片扩展名
- **THEN** 系统创建 `article_id` 为空的独立图片记录
- **AND** 返回该记录的图片 ID、预签名上传 URL 和公开访问 URL

#### Scenario: 图片扩展名不合法
- **WHEN** 管理员提交的图片扩展名不在允许列表内
- **THEN** 系统拒绝请求
- **AND** 不返回上传凭证和图片 ID

### Requirement: 图片对象路径不依赖文章
系统 SHALL 为图片生成 `article/img/<year>/<month>/<uuid>.<ext>` 格式的对象 Key，其中年月取签发上传凭证时的服务端时间，且对象 Key SHALL NOT 包含文章 ID。

#### Scenario: 新文章上传图片
- **WHEN** 管理员在尚未创建文章时申请图片上传凭证
- **THEN** 系统生成与文章 ID 无关的对象 Key
- **AND** 图片可以在文章创建前直接上传

#### Scenario: 编辑已有文章上传图片
- **WHEN** 管理员编辑已有文章并申请新图片上传凭证
- **THEN** 系统使用相同的独立图片路径规则
- **AND** 不移动文章正文中的已有图片对象

### Requirement: 正文持久化图片占位符
系统 SHALL 使用 `image://<image_id>` 表示由系统管理的文章图片，创建和更新文章时 SHALL 持久化该占位符而非当前公开域名下的完整图片 URL。

#### Scenario: 上传成功后插入图片
- **WHEN** 调用方使用预签名 URL 成功上传图片
- **THEN** 调用方在待保存正文中插入对应的 `image://<image_id>`
- **AND** 可以使用上传凭证响应中的公开访问 URL 实时展示图片

#### Scenario: 保存包含图片的正文
- **WHEN** 管理员创建或更新包含 `image://<image_id>` 的文章
- **THEN** 系统原样保存图片占位符
- **AND** 不将占位符改写为完整公开 URL

#### Scenario: 保留历史和外部图片地址
- **WHEN** 正文包含变更前保存的完整图片 URL 或外部图片 URL
- **THEN** 系统保持这些地址不变
- **AND** 不要求迁移为图片占位符

### Requirement: 保存文章时同步图片归属
系统 SHALL 根据正文中的图片占位符维护图片记录的 `article_id`，并 SHALL 保证文章内容和图片归属在同一数据库事务中提交。

#### Scenario: 创建文章时绑定图片
- **WHEN** 管理员创建包含一个或多个有效未绑定图片 ID 的文章
- **THEN** 系统创建文章后将对应图片的 `article_id` 更新为新文章 ID
- **AND** 文章和全部图片关系共同提交

#### Scenario: 更新文章时绑定新增图片
- **WHEN** 管理员更新文章并在正文中新增有效未绑定图片 ID
- **THEN** 系统将新增图片绑定到当前文章
- **AND** 已经绑定当前文章的图片保持不变

#### Scenario: 更新文章时移除图片
- **WHEN** 管理员更新文章并从正文移除已绑定图片 ID
- **THEN** 系统将对应图片的 `article_id` 更新为空
- **AND** 本次更新不删除图片对象和图片记录

#### Scenario: 正文引用无效归属图片
- **WHEN** 创建或更新正文引用不存在的图片 ID，或引用已绑定其他文章的图片 ID
- **THEN** 系统拒绝保存文章
- **AND** 不提交文章内容和任何图片关系变更

### Requirement: 文章详情返回已绑定图片映射
系统 SHALL 在公开文章详情和管理员编辑详情中返回原始正文，并 SHALL 为正文引用且绑定当前文章的图片生成 ID—URL 映射。

#### Scenario: 查询包含图片占位符的详情
- **WHEN** 文章正文包含一个或多个属于当前文章的 `image://<image_id>`
- **THEN** 系统返回未经 URL 替换的原始正文
- **AND** 批量返回对应图片的 ID 和当前公开访问 URL

#### Scenario: 更换图片公开域名
- **WHEN** 对象存储公开域名配置发生变化后再次查询文章详情
- **THEN** 图片映射使用新域名和图片记录中的对象 Key 生成 URL
- **AND** 文章正文无需修改

#### Scenario: 正文包含未绑定或错误绑定图片
- **WHEN** 历史或异常正文引用不存在、未绑定或绑定其他文章的图片 ID
- **THEN** 系统仍返回原始文章详情
- **AND** 图片映射不包含该无效关系

### Requirement: 硬删除时清理已绑定图片
系统 SHALL 在物理删除垃圾箱文章前查询该文章已绑定的图片，删除对应对象和图片记录；任一图片清理失败时 SHALL 保留文章及图片记录以允许重试。

#### Scenario: 硬删除包含已绑定图片的文章
- **WHEN** 管理员彻底删除一篇已处于垃圾箱的文章
- **THEN** 系统清理 `article_id` 等于该文章 ID 的图片对象
- **AND** 图片清理成功后删除图片记录和文章记录

#### Scenario: 已绑定图片清理失败
- **WHEN** 任一已绑定图片对象未能成功清理
- **THEN** 系统不物理删除文章记录和图片记录
- **AND** 返回错误以允许后续重试

#### Scenario: 硬删除没有已绑定图片的文章
- **WHEN** 管理员彻底删除没有已绑定图片的垃圾箱文章
- **THEN** 系统将图片清理视为成功
- **AND** 物理删除文章记录

## MODIFIED Requirements

### Requirement: 非硬删除阶段保留文章图片
系统 SHALL 在图片未绑定、文章为草稿、已发表或软删除状态时保留图片对象，并 SHALL NOT 因正文更新移除图片引用而立即删除对象。

#### Scenario: 更新正文移除图片
- **WHEN** 作者更新正文并删除对某张已绑定图片的引用
- **THEN** 系统保存新正文并将图片 `article_id` 更新为空
- **AND** 保留原图片对象和图片记录

#### Scenario: 文章软删除
- **WHEN** 作者将文章移入垃圾箱
- **THEN** 系统保留该文章的图片绑定关系和全部图片对象，以支持恢复

## REMOVED Requirements

### Requirement: 批量获取文章图片上传凭证
**Reason**: 编辑器按单张图片实时上传，批量接口及文章 ID 参数增加了不必要的耦合。

**Migration**: 调用方改用 `POST /article/image/upload-url`，每次为一张图片申请凭证。

### Requirement: 图片直接上传到文章正式目录
**Reason**: 图片对象改为独立资源，对象路径不再表达文章归属。

**Migration**: 新上传图片统一使用 `article/img/<year>/<month>/<uuid>.<ext>`；文章归属由图片记录的 `article_id` 表达，历史对象和正文 URL 保持不变。

### Requirement: 保存文章前等待图片上传完成
**Reason**: 单图片实时上传后，正文改为持久化图片 ID 占位符，不再在提交前批量替换为正式 URL。

**Migration**: 单张图片上传成功后在正文插入 `image://<image_id>`，文章保存时由系统同步图片归属。

### Requirement: 硬删除时清理文章目录
**Reason**: 新图片对象不再按文章 ID 分目录，硬删除改为根据图片记录中的 `article_id` 精确清理。

**Migration**: 使用“硬删除时清理已绑定图片”要求替代按对象前缀清理。
