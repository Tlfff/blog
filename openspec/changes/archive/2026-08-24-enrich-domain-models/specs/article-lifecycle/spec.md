## Purpose

定义单管理员即唯一作者模型下的文章创建、编辑、发布、移入垃圾箱、恢复和彻底删除规则，确保文章生命周期状态转换由领域模型统一保护，同时保持现有接口与调用流程。

## ADDED Requirements

### Requirement: 单管理员同时是唯一文章作者
系统 SHALL 将通过管理员中间件校验的唯一管理员账号视为文章作者，文章写操作继续使用当前登录用户 ID 作为作者身份，不新增多作者或独立授权模型。

#### Scenario: 管理员操作自己的文章
- **WHEN** 唯一管理员通过现有管理路由创建或操作文章
- **THEN** 系统使用当前登录用户 ID 作为文章作者 ID
- **AND** 不新增额外角色、作者映射或授权接口

### Requirement: 文章生命周期状态由领域规则保护
系统 SHALL 统一验证文章编辑、发布、移入垃圾箱和恢复的当前状态，并 SHALL 保持现有 Application 方法、HTTP 路由、请求字段和执行顺序兼容。

#### Scenario: 发布未删除文章
- **WHEN** 作者发布一篇未删除文章
- **THEN** 文章状态变为已发表

#### Scenario: 已删除文章不能编辑或发布
- **WHEN** 作者尝试编辑或发布已处于删除状态的文章
- **THEN** 系统返回现有文章已删除错误

#### Scenario: 恢复垃圾箱文章
- **WHEN** 作者恢复一篇已删除文章
- **THEN** 文章状态变为草稿
- **AND** 文章作者 ID 保持不变

### Requirement: 文章彻底删除前必须进入垃圾箱
系统 MUST 只允许彻底删除已处于删除状态的文章；未进入垃圾箱的草稿或已发表文章不得被直接彻底删除。

#### Scenario: 彻底删除垃圾箱文章
- **WHEN** 作者彻底删除一篇已处于删除状态的文章
- **THEN** 系统执行现有物理删除流程

#### Scenario: 拒绝直接彻底删除活动文章
- **WHEN** 作者尝试彻底删除草稿或已发表文章
- **THEN** 系统不执行物理删除
- **AND** 返回现有文章状态错误

### Requirement: 文章创建和编辑保持既有流程
系统 SHALL 在领域层保证文章创建和编辑后的状态合法，但 SHALL 保持现有数据库写入、图片转正、失败清理和 Repository 调用顺序。

#### Scenario: 创建包含临时图片的文章
- **WHEN** 管理员创建文章且正文包含临时图片
- **THEN** 系统先创建文章获得文章 ID，再执行图片转正和正文回写
- **AND** 图片转正失败时保持现有文章清理行为

#### Scenario: 编辑文章
- **WHEN** 作者编辑未删除文章
- **THEN** 系统保持先加载文章、处理新增临时图片、更新文章字段并保存的顺序
