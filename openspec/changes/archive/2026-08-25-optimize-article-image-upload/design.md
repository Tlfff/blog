## Context

当前 Article Application 在创建文章后或更新文章前扫描正文中的本站 URL，把 `article/temp/` 对象移动到 `article/<article_id>/`。MinIO 的移动实际由 CopyObject 和 RemoveObject 组成。新流程需要先获得文章 ID，并让浏览器直接把图片 PUT 到最终对象 Key。

现有文章表允许空字符串，但领域构造函数要求标题和正文非空；硬删除目前只删除数据库记录；Article 模块已经通过 `ArticleImageStorage` Port 隔离 MinIO 实现。

## Goals / Non-Goals

**Goals:**

- 保持 Article 的 Domain、Application、Infrastructure、Interfaces 分层。
- 不修改数据库结构，通过初始化空草稿获得文章 ID。
- 支持一次请求为不同扩展名的多张图片生成凭证。
- 标准创建和更新流程不再依赖临时目录和对象移动。
- 硬删除文章时按文章前缀清理全部图片，并提供可重试失败语义。

**Non-Goals:**

- 不跟踪正文中每一张图片的引用关系。
- 不在更新正文时删除已移除引用的图片。
- 不新增图片资产表、上传完成确认接口或后台孤儿图片清理任务。
- 不保证浏览器页面关闭后继续上传图片。

## Decisions

### 1. 使用独立初始化用例创建空草稿

在 Domain 层增加专用于初始化的构造行为，只接受作者 ID，创建 `StatusDraft` 且标题、正文为空的 Article；正常创建和编辑仍保持非空校验。Application 暴露初始化用例并返回文章 ID，HTTP 层新增初始化路由。

选择该方案是因为正式对象 Key 依赖数据库自增 ID，且不希望新增未完成状态或数据库字段。没有复用现有完整创建用例，因为它要求最终标题和正文，并会混淆“取得 ID”和“完成文章”的职责。

初始化后的完成动作复用现有更新用例，不新增“完成创建”用例。前端一次点击创建按钮，内部按初始化、上传、更新顺序编排。

### 2. 批量凭证请求按文件携带扩展名

HTTP 请求包含 `article_id` 和文件列表；每项至少包含 `client_id` 与 `file_ext`。响应为同样带 `client_id` 的结果列表，每项返回 `upload_url` 和正式 `url`。不同图片扩展名分别校验并生成对象 Key，不要求同一批文件类型一致。

Application 在签发凭证前加载文章，并调用领域权限规则确认当前用户是作者且文章未删除。批量输入先整体校验，再逐项生成凭证；任一输入非法时整个请求失败，不返回部分结果。

### 3. 图片直接写入不可变的文章正式路径

对象 Key 统一为 `article/<article_id>/<uuid>.<ext>`，预签名 PUT URL 继续使用当前有效期配置。Application 负责生成符合文章目录约束的 Key，Infrastructure 只负责签名和拼装公开 URL。

创建和更新直接保存前端替换完成的正式图片 URL。旧单张临时上传接口、`PromoteImages`、`MoveObject` 和 `article/temp/` 路径全部移除，不保留旧上传流程兼容入口。

### 4. 浏览器并发上传，但文章提交等待全部任务完成

调用方用稳定的本地标识关联编辑器占位符与批量凭证，获得凭证后可限制并发地异步 PUT 图片。异步表示不阻塞 UI，不表示忽略上传结果。只有全部 Promise 成功后，调用方才把占位符替换为正式 URL 并调用更新接口。

任一上传失败时不提交最终正文。页面关闭或刷新可能中断上传，因此前端应显示进度并在上传期间提示离开风险；本仓库不实现浏览器后台续传。

### 5. 硬删除先清理对象，再删除数据库记录

扩展 `ArticleImageStorage` Port，提供按前缀删除对象的能力。MinIO 适配器递归列出 `article/<article_id>/` 下的对象并删除，空目录视为成功。Application 在领域层确认文章已软删除且操作者有权限后，先调用图片清理 Port，再调用 Repository 物理删除。

如果对象清理失败，返回错误且不删除数据库记录，以便再次调用硬删除。若对象已删除但数据库删除失败，文章仍处于垃圾箱，重试时空目录清理成功后可继续物理删除。

### 6. 各层职责保持 DDD 边界

- Interfaces：绑定初始化和批量凭证请求，读取当前用户，转换响应。
- Application：编排文章查询、领域权限校验、对象 Key 生成、凭证签发和硬删除顺序。
- Domain：定义初始化草稿、作者权限、删除状态等业务规则，并声明图片存储 Port。
- Infrastructure：实现文章 Repository、MinIO 预签名和按前缀删除，不包含文章业务判断。

所有新增手写 Go 结构体字段、函数和流程均按仓库 `AGENTS.md` 添加中文注释及编号流程注释，修改文件统一执行 `gofmt`。

## Risks / Trade-offs

- [初始化后用户放弃创建会留下空草稿] → 空草稿保持可见并可继续编辑或由用户移入垃圾箱，本次不新增自动清理任务。
- [文章更新会留下不再引用的图片] → 接受额外存储占用，换取不误删和实现简单；硬删除时统一清理。
- [预签名成功不代表图片上传成功] → 前端必须等待 PUT 全部成功后再更新正文。
- [OSS 与数据库无法组成同一事务] → 采用“先对象、后数据库”的可重试顺序，并覆盖两阶段失败测试。
- [批量签发中途失败会产生未使用但短期有效的预签名 URL] → URL 有效期保持较短，且未执行 PUT 时不会产生对象。

## Migration Plan

1. 先增加 Domain 初始化行为、Application 用例、批量 DTO 和对象存储前缀删除能力，并补齐测试。
2. 新增初始化和批量凭证路由，保留现有文章更新接口作为完成创建与普通更新入口。
3. 管理端切换为“初始化或读取文章 ID、批量获取凭证、并发上传、等待完成、更新正文”。
4. 删除旧单张临时上传路由、图片转正和对象移动代码，并更新路由契约与兼容基线。
5. 回滚需要同时恢复旧后端接口与对应前端调用；新增空草稿仍是合法草稿，不需要数据迁移。
