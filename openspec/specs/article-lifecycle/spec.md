# Article Lifecycle Specification

## Purpose

定义单管理员即唯一作者模型下的文章创建、编辑、发布、移入垃圾箱、恢复和彻底删除规则，确保文章生命周期状态转换由领域模型统一保护，同时保持现有接口与调用流程。

## Requirements

### Requirement: 单管理员同时是唯一文章作者
系统 SHALL 将通过管理员中间件校验的唯一管理员账号视为文章作者，文章写操作继续使用当前登录用户 ID 作为作者身份，不新增多作者或独立授权模型。

#### Scenario: 管理员操作自己的文章
- **WHEN** 唯一管理员通过现有管理路由创建或操作文章
- **THEN** 系统使用当前登录用户 ID 作为文章作者 ID
- **AND** 不新增额外角色、作者映射或授权接口

### Requirement: 文章生命周期状态由领域规则保护
系统 SHALL 统一验证文章编辑、发布、移入垃圾箱和恢复的当前状态，并 SHALL 保持现有 Application 方法、HTTP 路由、请求字段和执行顺序兼容。

#### Scenario: 发布未删除文章
- **WHEN** 作者发布一篇未删除文章
- **THEN** 文章状态变为已发表

#### Scenario: 已删除文章不能编辑或发布
- **WHEN** 作者尝试编辑或发布已处于删除状态的文章
- **THEN** 系统返回现有文章已删除错误

#### Scenario: 恢复垃圾箱文章
- **WHEN** 作者恢复一篇已删除文章
- **THEN** 文章状态变为草稿
- **AND** 文章作者 ID 保持不变

### Requirement: 文章无需初始化草稿即可创建
系统 SHALL 允许管理员先独立上传正文图片，再通过现有文章创建能力直接保存标题、正文、标签和目标状态，不要求预先创建空草稿取得文章 ID。

#### Scenario: 直接创建包含图片的文章
- **WHEN** 管理员完成所需图片上传并提交包含图片占位符的创建请求
- **THEN** 系统直接创建文章记录并绑定正文引用的图片
- **AND** 不要求调用文章初始化接口

#### Scenario: 直接创建不包含图片的文章
- **WHEN** 管理员提交不包含系统图片占位符的创建请求
- **THEN** 系统继续按照既有规则创建文章

### Requirement: 文章创建和编辑保存图片占位符
系统 SHALL 在创建和编辑文章时继续执行既有标题、正文、作者和状态校验，并 SHALL 原样持久化正文中的 `image://<image_id>`，同时同步图片归属。

#### Scenario: 创建文章时保存图片占位符
- **WHEN** 管理员创建包含有效未绑定图片 ID 的文章
- **THEN** 系统直接保存正文中的图片占位符
- **AND** 将对应图片绑定到新文章

#### Scenario: 编辑文章时同步图片归属
- **WHEN** 管理员编辑未删除文章并提交包含新旧图片占位符的正文
- **THEN** 系统原样保存提交的正文
- **AND** 绑定新增图片并解绑已移除图片

### Requirement: 文章彻底删除前必须进入垃圾箱
系统 MUST 只允许彻底删除已处于删除状态的文章；未进入垃圾箱的草稿或已发表文章不得被直接彻底删除。系统 SHALL 在物理删除文章记录前清理 `article_id` 等于该文章 ID 的图片对象和记录。

#### Scenario: 彻底删除垃圾箱文章
- **WHEN** 作者彻底删除一篇已处于删除状态的文章
- **THEN** 系统先清理该文章已绑定的全部图片
- **AND** 图片清理成功后物理删除图片记录和文章记录

#### Scenario: 图片清理失败
- **WHEN** 作者彻底删除垃圾箱文章但任一已绑定图片未能清理
- **THEN** 系统不物理删除文章记录和图片记录
- **AND** 返回错误以允许后续重试

#### Scenario: 拒绝直接彻底删除活动文章
- **WHEN** 作者尝试彻底删除草稿或已发表文章
- **THEN** 系统不删除文章和图片数据
- **AND** 返回现有文章状态错误
